Overview

This API endpoint allows third-party systems to create customer invoice records in bulk. Customer invoices are created, confirmed, and automatically approved in a single transaction.

Important: Customer invoices are created in approved status and can be used immediately in transactions. The system automatically confirms and approves invoices created through this API.

Authentication

Required Headers

Header Type Description Example
Authorization string API authentication token {{SYSTEM_DESCRIPTION}} {{API_KEY}}
Content-Type string Must be application/json application/json

Request Structure

Root Object

Field Type Required Description
invoices array Required Array of invoice objects

Invoice Object Fields

Field Type Required Validation Description
invoice_type integer Required 1 or 2 1 = Direct Invoice (GL Code based), 2 = Item/Service Invoice
customer_code string Required Valid customer code Customer code or registration number
customer_invoice_number string Required Unique per customer External invoice number (must be unique for the customer)
currency_code string Required Valid currency code Currency code (e.g., USD, AED, EUR)
document_date string Required YYYY-MM-DD Invoice document date (must be within active financial period)
bank_code string Required Valid bank code Bank short code
account_number string Required Valid account number Bank account number matching the currency
comment string Required - Invoice comments/narration
segment_code string Conditional Valid segment code Required if invoice_type = 2 (Service Line Code)
warehouse_code string Conditional Valid warehouse code Required if invoice_type = 2
salesType integer Conditional 1, 2, or 3 Required if invoice_type = 2. 1 = Service, 2 = Inventory, 3 = User Quantity
details array Required At least 1 item Array of invoice detail objects

Invoice Detail Object Fields (Invoice Type 1 - Direct Invoice)

Field Type Required Validation Description
gl_code string Required Valid GL code Chart of Account code (must be non-control account)
segment_code string Required Valid segment code Service Line Code (must be approved and assigned)
uom string Required Valid unit code Unit of measure short code
quantity integer Required > 0 Invoice quantity
sales_price number Required > 0 Sales price per unit
discount_percentage number Optional >= 0 Discount percentage
discount_amount number Optional >= 0 Discount amount
vat_percentage number Optional >= 0 VAT percentage
vat_amount number Optional >= 0 VAT amount

Invoice Detail Object Fields (Invoice Type 2 - Item/Service Invoice)

Field Type Required Validation Description
service_code string Required Valid service/item code Item primary code (must match salesType category)
uom string Required Valid unit code Unit of measure short code
quantity integer Required > 0 Invoice quantity
sales_price number Required > 0 Sales price per unit
margin_percentage number Required >= 0 Margin percentage (required for invoice_type = 2)
userQty number Conditional >= 0 Required if salesType = 3
discount_percentage number Optional >= 0 Discount percentage
discount_amount number Optional >= 0 Discount amount
vat_percentage number Optional >= 0 VAT percentage
vat_amount number Optional >= 0 VAT amount

Response Format

Success Response (HTTP 200)

The response contains an array of successfully created invoices with their reference codes and invoice numbers.

{
  "success": true,
  "data": [
    {
      "ref": "INV-2026-000001",
      "invoiceNumber": "EXT-INV-001"
    },
    {
      "ref": "INV-2026-000002",
      "invoiceNumber": "EXT-INV-002"
    }
  ],
  "message": "Customer Invoice Created Successfully!"
}

Response Structure for Successful Creations

Field Type Description
success boolean Always true for successful response
data array Array of created invoice objects
data[].ref string Auto-generated booking invoice code (system reference)
data[].invoiceNumber string Customer invoice number from request
message string Success message

          "status": false,

Error Response Structure Details

Field Type Description
success boolean Always false for error response
message string Error message
code integer HTTP status code (422)
data array Array of error objects for each failed invoice
data[].identifier.unique-key string Customer invoice number identifying the failed invoice
data[].identifier.index integer 1-based index of the invoice in request array
data[].fieldErrors array Array of field-level errors (e.g., duplicate invoice number)
data[].headerData array Array containing header/master level validation errors
data[].detailData array Array containing detail line validation errors
data[].detailData[].errors[].index integer 1-based index of the detail line with error

Validation Rules

Root Level Validations

  1. invoices
    • Must be an array
    • Must contain at least one invoice object

Invoice Header/Master Validations

  1. invoice_type
    • Must be 1 (Direct Invoice) or 2 (Item/Service Invoice)
    • Must be an integer
  2. customer_code
    • Must be provided
    • Must exist in the system and be assigned to the company
    • Can be customer code or registration number
    • Customer must be active
  3. customer_invoice_number
    • Must be provided
    • Must be unique for the customer within the company
    • Cannot be used if already exists for the same customer
  4. currency_code
    • Must be provided
    • Must be a valid currency code
    • Currency must be assigned to the customer
  5. document_date
    • Must be provided in YYYY-MM-DD format
    • Must be a valid date
    • Must fall within an active financial year
    • Must fall within an active financial period for the month
  6. bank_code
    • Must be provided
    • Must be a valid bank short code
    • Bank must be active and assigned to the company
  7. account_number
    • Must be provided
    • Must be a valid bank account number
    • Account must match the bank code
    • Account currency must match the invoice currency
    • Account must be approved and active
  8. comment
    • Must be provided
  9. segment_code (Required if invoice_type = 2)
    • Must be provided if invoice_type = 2
    • Must be a valid Service Line Code
    • Segment must be active, not deleted, and approved
    • Segment must be assigned to the company
  10. warehouse_code (Required if invoice_type = 2)
    • Must be provided if invoice_type = 2
    • Must be a valid warehouse code
    • Warehouse must be active and belong to the company
  11. salesType (Required if invoice_type = 2)
    • Must be provided if invoice_type = 2
    • Must be 1 (Service), 2 (Inventory), or 3 (User Quantity)
  12. details
    • Must be provided as an array
    • Must contain at least one detail item

Invoice Detail Validations (Invoice Type 1 - Direct Invoice)

  1. gl_code
    • Must be provided
    • Must be a valid Chart of Account code
    • Account must be assigned to the company
    • Account must be active and non-control account
    • Account must not be a bank account
  2. segment_code
    • Must be provided
    • Must be a valid Service Line Code
    • Segment must be active, not deleted, and approved
    • Segment must be assigned to the company
  3. uom
    • Must be provided
    • Must be a valid unit of measure short code
    • Unit must be active
  4. quantity
    • Must be provided
    • Must be an integer
    • Must be greater than 0
  5. sales_price
    • Must be provided
    • Must be numeric
    • Must be greater than 0
  6. discount_percentage
    • Optional
    • If provided, must be numeric and >= 0
  7. discount_amount
    • Optional
    • If provided, must be numeric and >= 0
  8. vat_percentage
    • Optional
    • If provided, must be numeric and >= 0
  9. vat_amount
    • Optional
    • If provided, must be numeric and >= 0

Invoice Detail Validations (Invoice Type 2 - Item/Service Invoice)

  1. service_code
    • Must be provided
    • Must be a valid item primary code
    • Item must be assigned to the company and active
    • Item finance category must be 1, 2, or 4
    • If salesType = 1, item category cannot be 2 (Inventory)
    • If salesType = 2 or 3, item category must be 2 (Inventory)
  2. uom
    • Must be provided
    • Must be a valid unit of measure short code
    • Unit must be active
  3. quantity
    • Must be provided
    • Must be an integer
    • Must be greater than 0
  4. sales_price
    • Must be provided
    • Must be numeric
    • Must be greater than 0
  5. margin_percentage
    • Must be provided
    • Must be numeric
    • Must be >= 0
  6. userQty (Required if salesType = 3)
    • Must be provided if salesType = 3
    • Must be numeric
    • Must be >= 0
  7. discount_percentage
    • Optional
    • If provided, must be numeric and >= 0
  8. discount_amount
    • Optional
    • If provided, must be numeric and >= 0
  9. vat_percentage
    • Optional
    • If provided, must be numeric and >= 0
  10. vat_amount
    • Optional
    • If provided, must be numeric and >= 0

Business Rules

  • Invoices are automatically confirmed and approved upon creation
  • Invoice due date is automatically calculated based on customer credit days
  • Date of supply defaults to current date
  • Failed validations for one invoice don't prevent other invoices from being created
  • All invoices in a request are processed in a single transaction
  • If any invoice fails during storage, the entire transaction is rolled back
  • Document system mapping is created for successfully created invoices

Important Notes

  • Customer invoices are created in approved status and can be used immediately in transactions
  • The system automatically confirms and approves invoices created through this API
  • Invoice due date is automatically calculated based on customer credit days from the document date
  • Date of supply is automatically set to the current date
  • For invoice_type = 1 (Direct Invoice), you must provide gl_code and segment_code in details
  • For invoice_type = 2 (Item/Service Invoice), you must provide service_code in details and segment_code and warehouse_code at invoice level
  • When invoice_type = 2 and salesType = 3, the userQty field is required in details
  • The customer_invoice_number must be unique for each customer within the company
  • The document_date must fall within an active financial period
  • The account_number currency must match the invoice currency_code
  • For item invoices (invoice_type = 2), the service_code category must match the salesType:
    • salesType = 1 (Service): Item category cannot be Inventory (category 2)
    • salesType = 2 or 3 (Inventory/User Qty): Item category must be Inventory (category 2)
  • The API supports partial success - some invoices may be created while others fail validation, but if any invoice fails during storage, the entire transaction is rolled back
  • Document system mapping is automatically created for successfully created invoices to track the source system
